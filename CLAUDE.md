# Methods Study — notes for Claude

Photos of the user's Maths Methods work, sorted into topics automatically, with notes underneath (plain HTML/CSS/JS ES modules, no build step). Personal project, Cloudflare Worker `methods-study`. Started as a copy of `CaseoH231/Specialist-Study`; v2 added the study tools and a new design (light sidebar, graph-paper-pattern hero, Bricolage Grotesque headings, plum + mint). The shared parts (uploads, library ops, helper, Worker) still match Specialist – keep fixes in step.

- **"Do the weekly notes"** (or a scheduled Sunday run): follow `docs/WEEKLY.md`.
- The owner's library is `data/library.json` + `photos/<id>.jpg` on `main` in this repo. The app saves to it through the Worker (`/api/upload`, `/api/change`) with the GITHUB_TOKEN secret; changes are small ops (`lib.js` `applyOps`) applied to the newest copy, so the app and the weekly job never overwrite each other. Writes always need APP_PASSCODE.
- Sorting (`worker/sort.js`) and the helper (`worker/assistant.js`) use free Workers AI (Gemma 4, `env.AI`, thinking off) and are locked to OWNER_IPS / APP_PASSCODE (`worker/access.js`). The helper only suggests; the app applies after "Do it". Sorting only picks a topic and title – it doesn't transcribe.
- Friends see the owner's library read-only; their own photos stay on their device (IndexedDB + localStorage `methods-study-mine-v1`, ids start with `my-`).
- Course page (`#/course`, `course.js` + `worker/course.js`, the same files in bio-study, Specialist-Study and Methods-study – keep them identical): the owner uploads the study design and work plan (PDF/images) to `course/` in the repo via `/api/course` (APP_PASSCODE); everyone views them at `/course/<file>`.
- Study tools (Methods only, v2 design): `practice.js` (question generators – every answer is re-checked independently in `tests/test_tools.cjs`; add a matching check when adding a generator), `formulas.js` (formula sheet), planner (in `app.js`; shared dates are `events` in library.json via `add_event`/`delete_event` ops, friends' own dates are local `my-e…`), topic confidence ratings (local), share / print. Routes `#/practice`, `#/formulas`, `#/planner`, `#/course`. (The graph plotter was removed at the user's request; `tests/expr.mjs` keeps its formula reader for re-checking practice answers.)
- **Uploads only – the user's rule:** Methods is a study helper, not "AI help". The formula sheet and practice questions only show things that match the uploaded work (topic names + photo titles), via `unlock.js` – every generator and formula has `keys` (word starts) that must match. Nothing uploaded → locked. The helper bot only answers from the uploads and their notes; weekly notes stick to what's on the photo. Never add content that bypasses this.
- Run `bash tests/run_tests.sh` before pushing; it must PASS. Tests fake GitHub and the AI (`tests/fakes.cjs`) – never call the real ones.
- Each release: bump `CACHE` in `sw.js` (`methods-study-vN`) and add any new file to its FILES list.
- Deploy: `python3 tools/build_worker.py OUT && cd OUT && npx wrangler deploy` (packs the files into the Worker script). Data changes (library/photos) need no redeploy.
- Commit and push to `main`. Don't ask for permission to start; just do the work and push.
- After every change, summarise in plain language and end with `Total lines of code: N`, counted with:
  `find . -path ./.git -prune -o -path ./vendor -prune -o -path ./node_modules -prune -o -type f \( -name '*.js' -o -name '*.cjs' -o -name '*.py' -o -name '*.html' -o -name '*.css' -o -name '*.sh' -o -name '*.webmanifest' \) -print | xargs cat | wc -l`
